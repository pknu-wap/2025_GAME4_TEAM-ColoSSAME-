ColoSSAME Unity UI 적용 작업(브랜치 `origin/UI`, 2026-11-16 시작)에서 사용자가 정한 것과 겪은 것.

- **PR 단위**: 화면마다 PR 하나는 너무 많다고 함(2026-11-16). 종류별로 몇 화면씩 묶어 PR 본문에 기록 + 세션 보고. 첫 묶음 PR은 pknu-wap/2025_GAME4_TEAM-ColoSSAME-#170 (MainMenu·설정 + 공통 에셋, 초안). 2026-11-16 사용자 결정: 모든 UI를 PR 하나에 모으지 않고 화면 묶음별로 순서대로 merge — 같은 브랜치 origin/UI에서 #170 merge → main 반영 → 다음 묶음(로딩창·팀 선택 → 시설 6개 → 팀관리 등) 새 PR.
- **불러오기 버튼**: 저장 데이터가 없으면 비활성(숨기지 않음).
- **진행 방식**: 화면 하나 적용 → 푸시 → 검토 요청 후 멈춤. 승인 전에는 다음 화면으로 넘어가지 않음.
- **Unity MCP 주의**: Unity 창이 앞에 있지 않으면 명령이 응답하지 않는 경우가 있었음. Play Mode 진입 직후의 Game 뷰 스크린샷은 연결이 끊기며 Overlay UI가 빠진 화면이 찍힘 → 진입 후 `execute_code`로 한 번 응답을 확인한 뒤 찍을 것. 스크린샷은 화면당 최대 3장 제한.

- **진행 현황 (2026-11-19)**: #170(MainMenu·설정), #171(로딩창·팀 선택) merge 완료. 다음 묶음은 Notion "일" 화면(메인 화면 레이아웃)부터 새 PR.

**Why:** 사용자가 이후 화면들도 같은 방식으로 이어서 진행할 예정이라고 함.
**How to apply:** #170은 MainMenu·설정까지만. 로딩창은 #170 merge 후 새 PR에서 시작. 스크린샷 3장은 응답 확인 후 아껴서 사용.

- **토큰 절약 최우선 (2026-11-16, 사용자가 강하게 지적)**: Fable 5.2로 진행할 때 토큰이 너무 많이 든다고 해서 Opus 5.5로 바꿈. 큰 Hierarchy 덤프·스택트레이스·스크린샷 읽기·MCP 재시도를 줄이고, 시각 확인은 사용자에게 맡기며, 출력은 필요한 값만 받을 것.

- **작업 방식 (2026-11-18 사용자 승인, 토큰 절약)**:
  1. 새 화면 배치·레이아웃 변경·여러 에셋 조합 → Unity에 적용하기 전에 **HTML 시안**(1920×1080 비율, `Assets/Ui/...` PNG를 상대 경로로 참조, base64 금지, 위치·크기·글자색 숫자 표기)을 먼저 보여 주고 승인 후 적용.
  2. 스프라이트 교체·글자색·연결 수정처럼 결과가 분명한 작업 → 번호 목록 텍스트 계획으로 승인.
  3. 화면 묶음(PR) 하나가 끝나면 새 세션에서 시작. 맥락은 메모리·PR 본문·공유 노트에 남김.
  4. 확인 출력은 한 줄 요약, 이미지 확인은 승인 시안 한 장, 보고는 짧게.
